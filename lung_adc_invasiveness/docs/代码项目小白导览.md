## 1. 一句话理解项目

项目读取同一位病人的：

- 术前三维 CT：`data/raw/images/<patient_id>.nii.gz`
- 医生勾画的结节区域：`data/raw/masks/<patient_id>.nii.gz`
- 一行临床和 CT 语义信息：`data/raw/clinical.csv`

然后预测：

```text
0 = AIS / MIA
1 = IAC
```

这是一个**二分类预测模型流水线**，不是肺癌筛查，也不是预测病人未来是否患病。
研究对象是已经接受手术并有病理结果的特定人群；模型只在这个目标人群内工作。

### 三类材料不是同一种东西

| 材料 | 通俗理解 | 能不能直接作为模型输入 |
|---|---|---|
| CT | 三维影像，像素值表示 HU | 可以 |
| Mask | 医生圈出的结节位置，1 是结节，0 是背景 | 用于定位、裁剪和解释，不是病理答案 |
| `label` | 手术后的病理分类 | 训练时是答案；预测时绝对不能输入 |

### 项目里的“多模态”是什么

主要指：

1. CT 影像
2. 临床表，以及医生从 CT 上读出的语义特征，例如直径、CTR、毛刺、分叶

Radiomics 和 CNN 都从同一张 CT 提取信息，是两种**影像表示**，不是两种独立采集模态。
因此更准确的叫法是“影像 + 临床信息的联合模型”。

## 3. 整个项目就是一条七步流水线

`run_all.py` 不是自己完成所有计算，它像一个调度员，按顺序启动 `src/` 里的脚本。

```text
原始 CT / mask / clinical.csv
        |
        v
Step 0  生成模拟数据
        |
        v
Step 1  重采样、裁剪、分成三个队列
        |
        +---------------------+
        |                     |
        v                     v
Step 2 影像组学          Step 3 临床模型
        |                     |
        v                     |
Step 4 Rad-score              |
        |                     |
        +----------+----------+
                   |
                   v
Step 5  3D CNN：纯影像 + 影像/临床融合网络
                   |
                   v
Step 6  晚期融合、列线图、ROC、校准、DCA、SHAP
```

每一步都读写磁盘，而不是把全部中间结果塞在一个超长程序里。
这样你才能只重跑受影响的一步，并检查上一步是否真的成功。

### Step 0：生成模拟数据

文件：`src/00_make_demo_data.py`

作用：

- 生成 360 个模拟病人
- 生成 CT、mask、临床表和标签
- 制造中心 A / 中心 B 的层厚与噪声差异

真实数据不需要运行 Step 0，所以正式运行时使用：

```powershell
python run_all.py --real
```

### Step 1：影像预处理和分队列

文件：`src/01_preprocess.py`

核心动作：

1. 读取 CT 和 mask
2. 重采样到 `1 × 1 × 1 mm`
3. 以结节为中心裁出 `72³` 块
4. 保存为 `data/processed/patches/<patient_id>.npz`
5. 在 `meta.csv` 写入 `train / internal_test / external_test`
6. 生成 QC 图，检查 CT 和红色 ROI 是否对得上

为什么必须重采样：

不同医院的层厚不同。20 个体素在 1 mm 扫描里是 20 mm，在 2 mm 扫描里可能对应 40 mm。
统一物理尺度以后，形状和纹理才可比较。

为什么要裁块：

病人 CT 很大，而结节只占一小部分。裁掉无关区域后，影像组学和 CNN 都只处理病灶附近。

核心产物：

```python
{
    "image": 72 × 72 × 72 的 HU 数组,
    "mask":  72 × 72 × 72 的 0/1 数组
}
```

训练 CNN 时再随机裁 `64³` 做平移增强；验证和测试时从中心裁 `64³`。

### Step 2：提取影像组学特征

文件：`src/02_radiomics_extract.py`

影像组学可以理解为：

> 人为规定一组可计算的图像描述，例如形状、灰度分布、纹理，再从 CT 中批量算成一张数值表。

PyRadiomics 会从原图、LoG 滤波图和小波图上提取约一千多个特征。

例如：

```text
wavelet-LHL_glcm_Contrast
```

可以拆成：

- `wavelet-LHL`：先做某种小波分解
- `glcm`：看相邻灰度关系的纹理矩阵
- `Contrast`：对比度这一项统计量

ICC 用来检查：医生把边界稍微画大或画小一点，特征是否仍然稳定。
ICC 太低说明特征对勾画太敏感，不适合进入最终模型。

核心产物：

- `radiomics_features.csv`
- `radiomics_icc.csv`
- `02_radiomics_icc.png`

### Step 3：临床模型

文件：`src/03_clinical_model.py`

这一条线只使用临床和 CT 语义变量：

```text
age, sex, smoking, CEA, diameter, CTR,
lobulation, spiculation, pleural_indentation, vacuole
```

主要动作：

1. 生成 Table 1
2. 单因素 logistic 回归
3. 把 `p < 0.05` 的变量送入多因素回归
4. 向后剔除，保留一组变量
5. 输出每个病人的 `clinical_prob`

Logistic 回归做的事情可以写成：

```text
z = 截距 + b1×变量1 + b2×变量2 + ...
P(IAC) = 1 / (1 + exp(-z))
```

`z` 是 logit，`P(IAC)` 才是概率。
系数描述其他变量在场时的关联方向，不是“改变这个变量一定导致 IAC”的因果证明。

### Step 4：影像组学模型和 Rad-score

文件：`src/04_radiomics_model.py`

这是全项目最适合新手先读懂的传统机器学习脚本。

特征筛选漏斗：

```text
全部影像组学特征
  -> ICC 稳定
  -> 无非有限值、非常数
  -> Z-score 标准化
  -> Mann-Whitney U 检验
  -> 去除高度相关特征
  -> LASSO logistic
  -> 少量最终变量
```

LASSO 的作用：

- 它一边拟合分类，一边惩罚过大的系数
- 惩罚足够强时，一部分系数会变成 0
- 系数不为 0 的特征进入 Rad-score

`Rad-score` 是 LASSO 的线性得分，不是概率。对它做 sigmoid 才是 `radiomics_prob`。

训练集上使用 `cross_val_predict` 生成 OOF 分数：

> 每位训练病人的预测，都来自一个没见过他标签的折模型。

这是后面融合模型避免“自己考自己”的基础。

核心产物：

- `radiomics_signature.csv`
- `scores_radiomics.csv`
- `radiomics_pipeline.joblib`
- `04_lasso.png`
- `04_rad_signature.png`

### Step 5：深度学习

文件：`src/05_deep_learning.py`

有两个版本：

| 名称 | 输入 | 融合方式 |
|---|---|---|
| `image` | `64³` CT | 只看影像 |
| `image_clinical` | `64³` CT + 临床变量 | 影像向量与临床向量拼接后分类 |

v0 使用小型 `ResNet3D`：

```text
64³
 -> 32³
 -> 16³
 -> 8³
 -> 全局池化
 -> 128 维影像向量
 -> 1 个 logit
```

融合版多一条临床分支：

```text
10 个临床变量 -> 32 维
128 维影像 + 32 维临床 = 160 维
160 维 -> 1 个 logit
```

训练流程：

1. 训练集内部做 5 折
2. 每折训练一个模型
3. 验证折得到折外 logit
4. 内部测试和外部测试使用 5 个折模型的平均 logit
5. 固定训练轮数，取最后一轮，不拿验证折挑 epoch

Grad-CAM 的作用是看哪一块输入对当前输出响应较强。
它不是病灶分割，也不是因果解释。

### Step 6：融合与评价

文件：`src/06_fusion_evaluate.py`

比较六个模型：

1. Clinical
2. Radiomics
3. DL (image)
4. DL (image+clinical)
5. Late fusion
6. Nomogram

三种融合：

| 融合 | 做法 | 是否需要再训练 |
|---|---|---|
| 中间层融合 | 网络内部拼接影像向量和临床向量 | 是 |
| 晚期融合 | 三个单模态概率取平均 | 否 |
| 列线图 | 临床变量 + Rad-score + DL-score 再进 logistic | 是 |

主要评价图：

- ROC：排序能力
- 校准曲线：预测概率是否接近实际发生率
- Brier：概率预测误差
- DCA：在特定阈值代价下的净获益
- DeLong：两个模型在同一批病人上的 AUC 差异
- SHAP：变量如何推动当前模型输出

## 4. v0 和 v1 到底是什么关系

### v0：第一版可运行基线

v0 不是另一个仓库，而是当前代码在默认配置下运行出的结果：

```text
outputs/v0_baseline/
```

它具备：

- 模拟数据和真实数据入口
- 预处理和队列划分
- 临床、影像组学、3D CNN
- 融合和评价
- 图表、模型、日志和结果汇总

这一版的重点是：**把一个完整研究流程串起来。**

### 改进思路：先让实验可控，再谈性能

v1 以前，如果每做一个方案都直接改 `config.py`，会出现三个问题：

1. 不知道这次到底改了哪个参数
2. 新结果可能覆盖旧结果
3. 多改两个参数后，无法判断是谁造成的差异

所以 v1 首先加了实验管理，而不是急着堆更复杂的模型。

### v1 的实验管理代码

关键文件：

- `config.py`
- `experiments/*.json`
- `run_all.py`
- `compare_experiments.py`

一个实验就是一份 JSON：

```json
{
  "_note": "只改 LASSO 选 lambda 的规则",
  "LASSO_ONE_SE": false
}
```

运行：

```powershell
python run_all.py --exp v1c_lasso_min --base v0_baseline --steps 4,6
```

这里发生了四件事：

1. `--exp` 决定 `EXP=v1c_lasso_min`
2. `config.py` 读取 `experiments/v1c_lasso_min.json`
3. `run_all.py` 把基础实验结果复制到 `outputs/v1c_lasso_min/`
4. 只重跑 Step 4 和 Step 6

所以 v1a/v1b/v1c 是**同一套源码的三个实验配置**，不是三个互不相干的代码版本。

### v1a：瘤周影像组学

配置：

```json
{
  "PERITUMORAL_MM": 3
}
```

逻辑：

1. 原 mask 是结节本身
2. 把 mask 向外扩 3 mm
3. 用“外扩后区域 − 原 mask”得到瘤周环
4. 在环内再提一套特征，前缀为 `peri_`

目的：补充结节周围的毛刺、胸膜牵拉、周围磨玻璃等信息。

重跑：

```text
Step 2 重新提特征
Step 4 重新筛选和 LASSO
Step 6 重新融合评价
```

### v1b：2.5D 预训练 ResNet18

配置：

```json
{
  "DL_BACKBONE": "resnet18_2.5d",
  "DL_LR": 0.0003
}
```

做法：

1. 从 `64³` 块中取中心轴位、冠状位、矢状位
2. 三个二维切面当作 RGB 三个通道
3. 放大到 `128 × 128`
4. 输入 ImageNet 预训练 ResNet18

目的：小样本时借用预训练模型学到的通用边缘和纹理能力。

注意：这个实验同时改了网络和学习率，所以严格来说是“2.5D + 较小学习率”的组合实验，不是只改一个模型结构的单因素消融。

### v1c：LASSO 的 lambda 规则

配置：

```json
{
  "LASSO_ONE_SE": false
}
```

两种选法：

| 规则 | 含义 |
|---|---|
| `lambda_min` | 选交叉验证误差最低的模型 |
| `1-SE` | 在误差允许范围内选更强惩罚、更少特征的模型 |

`lambda_min` 不一定更好。它可能多保留一些特征，但只带来很小的误差改善。

### v1 同时修了两个工程问题

1. Grad-CAM 上采样后有约 3.5 个体素偏移，v1 修正了插值和末端补齐方式。
2. `--fast` 原来可能覆盖正式结果，现在默认写到 `outputs/smoke_fast/`，也不进入排行榜。

### v1 的模拟数据结果

训练集交叉验证 AUC：

| 模型 | v0 | v1a 瘤周 | v1b 2.5D | v1c lambda_min |
|---|---:|---:|---:|---:|
| Clinical | 0.855 | 0.855 | 0.855 | 0.855 |
| Radiomics | 0.803 | 0.802 | 0.803 | 0.807 |
| DL (image) | 0.768 | 0.768 | 0.726 | 0.768 |
| DL (image+clinical) | 0.834 | 0.834 | 0.745 | 0.834 |
| Late fusion | 0.852 | 0.848 | 0.825 | 0.856 |
| Nomogram | 0.864 | 0.862 | 0.855 | 0.863 |

结论：

- 三个 v1 改动在模拟数据上都没有稳定、明确的提升
- 默认主结果仍保留 v0
- v1 真正有价值的成果是**可复现实验工具和更可检查的流程**

最重要的教学点不是“哪个模型赢”，而是：

> 不能看到内部测试集分数变高就采纳方案。选方案应该看训练集内部的交叉验证，测试集只用于最终评价。

例如 v1b 的纯影像 DL：

- 训练集 CV AUC：`0.768 -> 0.726`，变差
- 内部测试 AUC：`0.701 -> 0.750`，看起来变好

如果盯着内部测试挑方案，就会把一个在开发阶段表现更差的方案选进来。
内部测试只有 78 人，0.05 的波动完全可能是样本波动。

## 5. 这套代码现在能做什么，不能吹什么

### 已经做得较好的部分

- 全流程能运行并产出图表、表格、模型和日志
- 模拟数据有明确水印
- 训练、内部测试、外部测试分开
- 影像组学的外层交叉验证把筛选和 LASSO 包进 Pipeline
- 训练集融合使用 OOF 分数
- 测试集阈值沿用训练集，不在测试集重新挑阈值
- 实验配置、输出目录和排行榜已经形成基本秩序

### 在换成真实数据前必须继续修的部分

`docs/代码审阅与项目讲解_2026-11-06.md` 已经指出几个重要问题：

1. 临床模型的变量选择目前发生在 5 折之前，OOF 还不是完整建模流程的严格折外预测。
2. 列线图对 OOF 分数再次做交叉验证，仍有间接泄漏风险。
3. 读取 NIfTI 时丢了 affine，真实数据必须核对方向、原点和物理坐标。
4. 没有第二读者 mask 时，扰动 mask 只能叫“分割扰动稳健性”，不能冒充真实读者间 ICC。
5. 实验只隔离 `outputs/`，没有隔离原始数据、预处理和队列版本。
6. 还没有一个能加载全部融合组件、直接给新病人推理的部署入口。

所以“拿到真实数据直接替换，代码不用改”这句话说过头了。
更准确的表述是：

> 模拟数据已经跑通整条研究流水线；真实数据到来前，还要先修验证设计、影像几何和实验追溯。

## 10. 最容易混淆的五个概念

### 1. AUC 不是准确率

AUC 可以理解为：随机取一个 IAC 和一个 AIS/MIA，模型把 IAC 排得更高的概率。
它不依赖某一个固定阈值，所以不能直接说成“诊断准确率”。

### 2. 概率不是分类结果

模型先输出 `P(IAC)`。
再选定阈值，例如 `0.5`，才把它变成 0 或 1。
换阈值不需要重新训练模型。

### 3. 验证集不是测试集

验证数据用于开发阶段做决定；测试集用于最后评价。
如果反复看测试集改参数，测试集就在事实上变成训练信息的一部分。

### 4. OOF 不是普通预测

OOF 表示每位训练病人的预测来自一个没有见过他标签的折模型。
但如果筛选、填补或融合本身用了全体训练集标签，泄漏仍然可能存在。

### 5. 融合不保证更好

两个模态如果重复表达同一个信息，拼接后可能只增加噪声、维度和不稳定性。
融合是否有价值，必须在同一批病人、同一划分和同一评价协议下做消融比较。

## 11. 新手排查顺序

遇到报错时不要从“改模型”开始，按下面顺序查：

1. `ModuleNotFoundError`
   - 当前 Python 是不是 `F:\MED5085\env\python.exe`？
2. `FileNotFoundError`
   - 当前目录是不是项目根目录？
   - `data/processed/meta.csv` 是否存在？
3. 某个病人缺 CT 或 mask
   - 看 `clinical.csv` 的 ID 和文件名是否完全一致
4. shape 不匹配
   - 打印 image、mask、模型输入和输出 shape
5. CUDA 不可用
   - 先用 CPU 或 `--fast` 验证逻辑，不要同时排查数据和驱动
6. 分数高得异常
   - 优先查患者重复、时间泄漏、标签错位、预处理泄漏
